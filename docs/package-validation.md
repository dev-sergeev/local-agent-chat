# Проверка устанавливаемого пакета

Проверено 13 сентября 2026 года на Linux/aarch64 с Python 3.12. Пакет `local-agent-chat` версии `0.1.0` собирается в wheel и sdist; `twine check` принимает оба файла. Wheel содержит точку входа `localchat`, приложение, конфигурацию Chainlit, переводы, страницы приветствия, изображения, CSS, JavaScript и примеры настроек.

## Автоматические проверки

- Полный набор: **173 passed, 31 subtests passed**. Предупреждение об устаревающем Pydantic API относится к зависимости `traceloop`.
- `ruff check`, `ruff format --check`, `compileall`, `bash -n`, `git diff --check` прошли. Оба GitHub workflow проверены `actionlint`.
- CLI проверен на интерактивную и автоматическую настройку, приватные права файлов, буквальное сохранение ключей, отказ от перезаписи конфигурации, приоритет environment и разрешение относительных путей. Help/version не создают служебных файлов.
- Отдельные проверки запускают настоящий процесс CLI, создают состояние TCP `TIME_WAIT`, затем останавливают сервер через SIGTERM и SIGINT. Данные остаются, временный каталог удаляется; повторный запуск на том же порту разрешён.

`scripts/check_distribution.py` установил wheel с обычными runtime-зависимостями в новый venv вне checkout. Импорт подтвердил загрузку из `site-packages` этого окружения. Через локальную модель-имитатор проверены:

1. Загрузка JS/CSS и UI по полному префиксу прокси.
2. Загрузка `note.txt`, реальный вызов `read_file` и возврат контрольного текста.
3. Пять запросов; редактирование третьего с удалением продолжения и точным соответствием истории UI и runtime SQLite.
4. Остановка, переустановка wheel, сохранение конфигурации и возобновление того же чата.
5. Новый запрос и правка первого; отсутствие поздних запросов в текущем контексте модели.
6. `integrity_check`, `foreign_key_check`, пустые временные архивы Revision, отсутствие ошибок SQLite в логах.
7. Очистка временных файлов при остановке и отсутствие записей в каталог, из которого пользователь запустил команду.

Эта проверка включена в CI для Python 3.12 и 3.13. Workflow публикации повторяет её для wheel, скачанного из TestPyPI, и сверяет его SHA-256 перед отправкой тех же дистрибутивов в PyPI.

## Браузер

Установленный wheel запущен из `/tmp` через `localchat run` и открыт в Chromium по публичному маршруту JupyterHub. Через UI загружен файл, выполнены пять запросов, изменён третий запрос и перезагружена страница. Идентификаторы первых трёх запросов сохранились, первые два запроса/ответа не изменились, четвёртый и пятый исчезли из текущей истории. После каждого запроса, редактирования и перезагрузки полные тексты запросов и ответов в UI совпали с SQLite. Необработанных ошибок JavaScript нет.

Во время проверки использовалась управляемая локальная модель, поэтому этот прогон не оценивает качество ответов внешнего LLM-провайдера. Предыдущая проверка реальной модели и глубины 100 запросов описана в [ReAct validation](react-validation.md).

## Исправления, найденные при упаковке

Chainlit завершает процесс через `os._exit()`, поэтому Python-finalizers вокруг его CLI не выполнялись. Теперь родительский процесс владеет временным каталогом и очищает его после завершения дочернего сервера; приложение закрывает свои ресурсы до завершения lifespan Chainlit. Проверка порта использует `SO_REUSEADDR`, чтобы TCP `TIME_WAIT` после штатной остановки не запрещал немедленный перезапуск.

Локальные журналы, JSON-проверки и скриншоты находятся в `/tmp/localchat-package-validation-3` и `/tmp/localchat-browser`; они не включаются в Git или дистрибутивы. Тестовые процессы после проверки остановлены. Публикация на внешних индексах требует настройки Trusted Publisher владельцем аккаунтов; локальная сборка и проверка сами по себе не означают публикацию.
