# Security

## Модель использования

Проект рассчитан на одного доверенного пользователя внутри внешне изолированного Jupyter-контейнера или VM. Не публикуйте порт приложения напрямую: header-auth полагается на аутентификацию JupyterHub.

Оба Agent Mode структурно предоставляют только `ls`, `read_file`, `glob` и `grep`. Общих инструментов создания, изменения, удаления файлов, запуска shell-команд или кода у Agent нет. Узкие `remember_context` и `forget_context` изменяют только управляемый приложением файл Long-term Memory и не дают произвольной записи.

Chat Files Agent Mode по умолчанию ограничивает файловые инструменты виртуальным корнем Uploaded Files текущего Chat. Отдельный read-only маршрут к доверенной папке Project Skills позволяет загружать их инструкции в обоих режимах, но не открывает остальной host. Проверки путей и символических ссылок не позволяют Uploaded File вывести Agent за эту область. Это прикладная граница доступа, а внешнюю изоляцию сервиса по-прежнему должен обеспечивать контейнер или VM.

Host Files Agent Mode разрешает чтение и поиск по абсолютным host-путям, которые доступны процессу приложения. Прочитанное содержимое может быть передано выбранному model provider; не запускайте этот режим рядом с секретами или данными, которые провайдер не должен получить. Выбор фиксируется при первом Turn и не может быть изменён через Revision, checkpoint или metadata.

Global Memory индексирует только пользовательский текст и публичные ответы активных Turn в локальном SQLite. Она не индексирует tool logs, checkpoint, snapshot tokens или содержимое файлов; результаты прошлых Chat передаются модели только при явном вызове read-only retrieval tool и считаются недоверенными данными.

Long-term Memory хранится локально в ограниченном Markdown-файле с правами `0600`, но её актуальный снимок передаётся выбранному model provider в каждом Turn как недоверенные справочные данные. Инструмент записи отклоняет распознаваемые пароли, API keys, access tokens и private keys, а загрузчик фильтрует такие записи из вручную изменённого файла; это защитная эвристика, а не замена правилу никогда не помещать credentials или секреты в память. System prompt запрещает переносить инструкции из файлов и tool output в долговременную память, но решение о записи принимает модель, поэтому это не является жёсткой границей против persistent prompt injection. У delegated Agent нет узких memory-mutation tools. Host Files может прочитать сам файл памяти, если процесс имеет доступ к его абсолютному пути, но общий инструмент для изменения этого файла отсутствует.

## Сообщение об уязвимости

Используйте private security advisory репозитория. Не публикуйте эксплойты, токены или пользовательские данные в обычных Issues.
