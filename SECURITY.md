# Security

## Модель использования

Проект рассчитан на одного доверенного пользователя внутри внешне изолированного Jupyter-контейнера или VM. Не публикуйте порт приложения напрямую: header-auth полагается на аутентификацию JupyterHub.

Read-only Agent Mode структурно исключает инструменты записи, удаления и исполнения, но его инструменты чтения и поиска видят все host-файлы, доступные процессу приложения. Их содержимое может быть передано выбранному model provider, поэтому экземпляр должен работать только с доверенным пользователем и в специально выделенной файловой среде.

Extended Agent Mode использует отдельный для Chat Python `venv` и минимальное environment без ключей модели. Это не даёт обычным `python`/`pip` менять зависимости сервиса, но не превращает `LocalShellBackend` в security sandbox. Команды и файловые инструменты могут читать и изменять доступные host-файлы, обращаться к сети и системным программам. Revision откатывает только Chat-owned файлы и служебные артефакты, а не произвольные host-пути. Настоящую границу должен обеспечивать отдельный контейнер или VM.

Global Memory индексирует только пользовательский текст и публичные ответы активных Turn в локальном SQLite. Она не индексирует tool logs, checkpoint, snapshot tokens или содержимое файлов; результаты прошлых Chat передаются модели только при явном вызове read-only retrieval tool и считаются недоверенными данными.

## Сообщение об уязвимости

Используйте private security advisory репозитория. Не публикуйте эксплойты, токены или пользовательские данные в обычных Issues.
