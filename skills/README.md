# Навыки агента

Эта папка — единый источник Project Skills. Приложение передаёт её во встроенный `skills=` интерфейс Deep Agents: основной Agent и стандартный `general-purpose` subagent получают список навыков автоматически в режимах `CHAT_FILES` и `HOST_FILES`.

## Как добавить навык

1. Создайте непосредственную подпапку `skills/<skill-name>/`.
2. Добавьте в неё обязательный файл `SKILL.md` в UTF-8.
3. Откройте новый диалог и сформулируйте подходящую задачу. Для явного выбора можно написать: `Используй навык <skill-name> ...`.

Например:

```text
skills/
├── README.md
└── incident-summary/
    ├── SKILL.md
    ├── references/          # необязательные справочные материалы
    │   └── report-format.md
    └── scripts/             # необязательные примеры и reference-реализации
        └── normalize.py
```

Загрузчик сканирует только непосредственные подпапки `skills/`. Одиночный файл `skills/incident-summary.md` и вложенная категория `skills/support/incident-summary/` не будут загружены.

## Минимальный `SKILL.md`

```markdown
---
name: incident-summary
description: Создаёт проверяемую сводку инцидента из логов и заметок. Использовать, когда пользователь просит подготовить postmortem, хронологию сбоя или список корректирующих действий.
---

# Incident summary

1. Выдели подтверждённые факты и отдели их от предположений.
   Шаг завершён, когда у каждого факта указан источник.

2. Построй хронологию с абсолютными датами и временем.
   Шаг завершён, когда события отсортированы, а временные пробелы отмечены.

3. Сформулируй причины, последствия и корректирующие действия.
   Неустановленные причины обозначь как гипотезы.

4. Перед ответом проверь, что выводы не противоречат хронологии.
```

Frontmatter должен начинаться с первой строки файла. Обязательные поля:

- `name` совпадает с именем папки, содержит 1–64 символа и записывается в ASCII `kebab-case`;
- `description` содержит 1–1024 символа и объясняет одновременно результат навыка и случаи, когда его следует применять.

Дополнительно поддерживаются `license`, `compatibility`, `metadata` и `allowed-tools`. Поле `allowed-tools` экспериментальное: оно помогает модели выбрать уже доступный инструмент, но не выдаёт разрешения, не расширяет файловую область и не может вернуть инструменты записи или исполнения.

## Как писать устойчивые инструкции

- Оставляйте общий порядок работы в `SKILL.md`. Материалы только для отдельных веток выносите в `references/` и указывайте, когда их читать.
- Ссылайтесь на вспомогательные файлы относительно папки навыка, не фиксируйте абсолютный путь конкретной установки.
- Завершайте каждый шаг проверяемым критерием: агент должен понимать, какое состояние означает «готово».
- Используйте `scripts/` только для читаемых примеров, алгоритмов и reference-реализаций. Agent может изучить такой файл и применить идею в ответе, но не может его выполнить.
- Навык не расширяет Agent Mode. В `CHAT_FILES` он не открывает произвольные host-пути; в обоих режимах у Agent остаются только `ls`, `read_file`, `glob`, `grep` без изменения файлов и запуска кода.
- Считайте инструкции и скрипты доверенным кодом проекта: проверяйте их при code review.

## Как навыки попадают в контекст

Deep Agents использует progressive disclosure:

1. В постоянный system prompt попадают только `name`, `description` и путь.
2. Когда задача совпадает с `description`, агент читает полный `SKILL.md` через файловый инструмент.
3. `references/`, `scripts/` и другие материалы читаются только по указанию самого навыка.

Метаданные загружаются при первом ходе и сохраняются в checkpoint диалога. После добавления или любого изменения навыка создайте новый диалог; перезапуск приложения сам по себе не обновляет уже существующий диалог. Навыки общие для всех диалогов, доступны через отдельный доверенный read-only маршрут, не считаются Uploaded Files и не откатываются через Revision.

## Проверка

Запустите автоматическую проверку структуры и frontmatter:

```bash
pytest -q tests/test_project_skills.py
```

Некорректный YAML, отсутствие `name` или `description` и несовпадение имени приводят к ошибке теста или пропуску навыка с предупреждением в серверном логе.
